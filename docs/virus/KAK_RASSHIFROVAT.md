# Как полностью расшифровать APK

В APK два уровня «шифрования»:

---

## 1. Записи в ZIP под паролем

Часть файлов в архиве (в т.ч. `classes.dex`, `AndroidManifest.xml`) может быть зашифрована паролем ZIP. Обычный распаковщик их не возьмёт без пароля.

### Варианты

**A) Apktool и JADX читают APK сами**  
Они работают с файлом APK напрямую и часто умеют обходить такую защиту или читать только нужные данные. Стоит попробовать в первую очередь:

```bash
apktool d "⬅️TAKLIFNOMA TOY AVGUST 1325478967.apk" -o apk_decoded
jadx-gui "⬅️TAKLIFNOMA TOY AVGUST 1325478967.apk"
```

Если apktool/jadx открывают APK и показывают манифест и код — для анализа этого достаточно, пароль ZIP искать не обязательно.

**B) Перебор пароля ZIP**

- **fcrackzip** (Linux/WSL):
  ```bash
  fcrackzip -u -D -p /usr/share/wordlists/rockyou.txt "⬅️TAKLIFNOMA TOY AVGUST 1325478967.apk"
  ```
- **7-Zip** (Windows): открыть APK как архив, ввести пароль при запросе или попробовать свои варианты.
- **Словарь**: свой список паролей в файле, затем перебор (fcrackzip `-p wordlist.txt` или скрипт с `pyzipper`).

**C) Поиск пароля в приложении**  
Если удастся получить код (например, через JADX по другому DEX или по уже распакованным строкам) — искать в строках/константах что-то вроде пароля (короткие строки, передача в функцию расшифровки и т.п.).

---

## 2. «Расшифровка» бинарных форматов (сделать читаемым)

Даже после распаковки часть файлов — бинарные, их нужно именно **декодировать**, а не «взламывать пароль»:

| Файл | Что это | Чем расшифровать |
|------|--------|-------------------|
| `AndroidManifest.xml` | бинарный AXML | **apktool** или **aapt** |
| `classes.dex` | байткод Dalvik/ART | **jadx** (→ Java), **apktool** (→ smali) |
| `resources.arsc` | скомпилированные ресурсы | **apktool** |
| `res/*` | скомпилированные XML/drawable | **apktool** |

То есть «полная расшифровка» в смысле «всё в читаемый вид» делается так:

1. **apktool** — одна команда даёт читаемый манифест, ресурсы и smali:
   ```bash
   apktool d "⬅️TAKLIFNOMA TOY AVGUST 1325478967.apk" -o apk_decoded
   ```
   В `apk_decoded` будут:
   - `AndroidManifest.xml` (нормальный XML)
   - `res/` с расшифрованными XML
   - `smali/` — код в виде smali (если DEX удалось извлечь)

2. **JADX** — из DEX получаешь Java:
   - Открыть в **jadx-gui** тот же APK или папку `apk_decoded`.
   - Искать логику вируса по классам/методам.

---

## Кратко

- **Сначала**: `apktool d file.apk -o apk_decoded` и `jadx-gui file.apk` — часто этого хватает для полного анализа, даже если часть ZIP под паролем.
- **Если нужны именно зашифрованные файлы из ZIP**: перебор пароля (fcrackzip, 7z, свой словарь) или поиск пароля в коде/строках приложения.
- **«Расшифровать» манифест/DEX/ресурсы** = декодировать бинарники с помощью apktool и JADX, как в таблице выше.
